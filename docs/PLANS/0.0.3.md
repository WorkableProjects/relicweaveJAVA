# RelicWeave 0.0.3 — Attunement Update Plan

**Target:** Minecraft 1.20.1 · Minecraft Forge 47.3.0+  
**Status:** Proposed roadmap; features below are not assumed to be implemented.  
**Theme:** **Attunement** — expand equipment customization, add useful relics, and make both machines communicate their state clearly without introducing another material tier.

## Goals and scope

- Add optional Curios support while preserving full functionality without Curios.
- Add 6 relics, 6 Transmutation Table enchantments, and 4 Celestial Infuser infusions.
- Give every mapped source item **both** a Transmutation enchantment and a Celestial Infuser infusion. The same item type can be used in either machine's separate recipe path; it does not apply both effects to equipment at once.
- Add restrained completion feedback and explicit machine status messages.
- Update tooltips, guidebook/JEI support, server configuration, and regression tests.
- Preserve existing 0.0.2 items, recipes, infusion behavior, and saved player data.

## 1. Source-item mapping: enchantment **and** infusion

The table below is the proposed mapping for the update. **No row may define only an enchantment or only an infusion.** Each source item must have a valid mapping for both systems, even though the resulting effects are applied through separate machines. The listed vanilla item IDs are candidate catalysts, not a claim about the current 0.0.2 recipe registry. During implementation, compare them with the existing recipe/item registry and reuse suitable existing inputs where possible; do not create a new ore/material tier just to satisfy this table.

| Source item / candidate recipe catalyst | Transmutation Table — enchantment output | Celestial Infuser — infusion output |
| --- | --- | --- |
| Prismarine Shard (`minecraft:prismarine_shard`) | **Undertow I–III** — trident | **Tidal** — helmet |
| Echo Shard (`minecraft:echo_shard`) | **Resonance I–III** — pickaxe | **Warding** — chestplate |
| Phantom Membrane (`minecraft:phantom_membrane`) | **Steady Draw I–II** — bow | **Pursuit** — leggings |
| Copper Ingot (`minecraft:copper_ingot`) | **Reprisal I–III** — shield | **Anchored** — boots |
| Ghast Tear (`minecraft:ghast_tear`) | **Soulguard I–II** — chestplate | **Warding** — chestplate |
| Oak Sapling (`minecraft:oak_sapling`) | **Reaping I–III** — hoe | **Anchored** — boots |

### Mapping rules

- Treat each row as two independent recipe definitions: one recipe for the enchantment/book pathway and one for the infusion pathway.
- A source item listed here is intentionally associated with **both** outputs. Do not implement it as a one-sided mapping.
- An item may share an infusion with another source item; this table intentionally maps Warding and Anchored to more than one source item.
- Keep the exact source-to-effect relationship data-driven where practical. The UI, guidebook, JEI entries, and recipe validation should read from the same canonical mapping so they cannot disagree.
- If the existing 0.0.2 registry uses a different item for one of these roles, update the item ID while preserving both output columns. Document the final IDs in the release changelog.
- Do not reuse Iron Ingots (`minecraft:iron_ingot`) or Nether Stars (`minecraft:nether_star`) for these new mappings: the existing 0.0.2 plan already assigns them an enchantment and an infusion. Copper Ingots and Ghast Tears are replacement candidates, pending an audit of all existing 0.0.2 recipes and registry mappings.
- Balance catalyst quantities and recipe costs against current progression; avoid introducing an unintended bottleneck.
- Add validation/tests that fail when any configured source item is missing either its enchantment mapping or its infusion mapping.

## 2. Optional Curios integration

Curios support is optional. RelicWeave must load and remain playable when Curios is absent.

- Support eligible charms from inventory or a compatible Curios slot.
- Prefer the existing `charm` slot category where appropriate. Ensure compatible slots actually exist; do not assume Curios provides usable slots automatically.
- Prevent duplicate effects when a charm exists in multiple locations or a player carries duplicates.
- Keep existing hand requirements for totems by default. Add a server configuration option to allow Curios activation only after its balance implications are tested.
- Moving, dropping, equipping, unequipping, dying, respawning, or reconnecting must not reset an active relic cooldown.
- Tooltips must describe valid locations, activation behavior, cooldown, and whether duplicates stack.
- Provide server settings for **inventory-or-equipped** versus **equipped-only** charm activation.
- Avoid adding a new Curios slot for every relic unless testing demonstrates a real need.

## 3. Six new relics

The following are proposed new relics. They should provide distinct gameplay options rather than duplicate passive-stat bonuses.

| Relic | Proposed effect | Limits / requirements |
| --- | --- | --- |
| **Lodestone Charm** | Pulls nearby dropped items toward the player. | Short range; toggleable; respects pickup restrictions and item ownership rules. |
| **Tidal Charm** | Grants water breathing and improved underwater visibility. | No additional damage or armor bonus. |
| **Featherwoven Charm** | Reduces fall damage and briefly applies slow falling after a dangerous fall. | No flight or unlimited hovering. |
| **Wayfarer's Relic** | Activated return to a deliberately bound location. | Long cooldown and channel time; initially same-dimension only; cancel safely if interrupted. |
| **Echo Charm** | Briefly highlights nearby hostile creatures when activated. | Limited radius and duration; cooldown prevents continuous scanning. |
| **Guardian Relic** | Grants a short absorption shield when health becomes critical. | Long cooldown; must not prevent death by itself or stack without a cap. |

### Active relic controls

- Prefer one **Activate Relic** keybind instead of adding a separate keybind for every relic.
- Provide an unambiguous way to select the active relic and show the selected relic in the HUD or tooltip.
- Define server-side validation, cooldown handling, and target checks so clients cannot bypass restrictions.
- Do not let equipping, unequipping, switching inventory slots, or moving an item between inventory/hands/Curios reset cooldowns.

## 4. Six Transmutation Table enchantments

These enchantments follow the existing enchanted-book/anvil progression and remain distinct from Celestial Infuser infusions.

| Enchantment | Max level | Equipment | Effect | Balance requirements |
| --- | --- | --- | --- | --- |
| **Reaping** | III | Hoes | Harvests mature crops in an increasing area and replants where seeds are available. | Define radius per level; charge appropriate durability; consume/reuse seeds correctly; never harvest immature crops. |
| **Undertow** | III | Tridents | Hitting a submerged target briefly slows it and improves the wielder's swimming speed. | Short duration; define how it behaves against bosses and aquatic mobs. |
| **Resonance** | III | Pickaxes | Consecutive mining of the same block type builds a small mining-speed bonus; switching block types resets it. | Set a strict speed cap and decay/reset rules; decide whether it conflicts with Conductive or shares a combined speed cap. |
| **Soulguard** | II | Chestplates | Killing a hostile mob grants a small temporary absorption shield. | Cap absorption; prevent unlimited accumulation and rapid farming exploits. |
| **Steady Draw** | II | Bows | Reduces movement slowdown while drawing a bow. | Does not increase arrow damage or bypass other draw restrictions. |
| **Reprisal** | III | Shields | A well-timed block briefly weakens the attacker. | Reward successful timing rather than holding a shield indefinitely; define a short debuff and internal cooldown. |

## 5. Four Celestial Infuser infusions

Infusions are applied to Celestial armor through the Celestial Infuser. Keep the current three-infusion limit: more options should create trade-offs rather than permit every effect at once.

| Infusion | Armor piece | Effect | Balance requirements |
| --- | --- | --- | --- |
| **Tidal** | Helmet | Grants water breathing while submerged. | Avoid duplicating stronger existing effects without a deliberate compatibility rule. |
| **Anchored** | Boots | Crouching greatly reduces incoming knockback. | Define the reduction cap; should not make the wearer completely immovable. |
| **Warding** | Chestplate | Periodically prepares a small shield against the next hit. | One prepared charge maximum; no charge stacking; define refresh timing and hit interactions. |
| **Pursuit** | Leggings | Grants a brief movement-speed burst after defeating a hostile mob. | Short duration and internal cooldown; prevent chaining into permanent speed. |

### Infusion stacking and compatibility

- Explicitly define whether the same infusion on multiple armor pieces can stack. Default recommendation: identical infusion effects do not stack; use the strongest single instance or a single shared effect instance.
- Preserve the three-infusion limit and validate it server-side.
- Explain active effects, armor-piece restrictions, stacking rules, and conflicts in both machine UI and item tooltips.
- Make infusion application/removal and armor swaps safe across death, respawn, reconnects, and dimension changes.

## 6. Machine feedback and polish

### Transmutation Table

- Play a distinct magical completion sound and emit a brief rune-particle burst after successful completion.

### Celestial Infuser

- Play a deeper resonance followed by a short celestial chime after successful completion.

### Shared requirements

- Play completion feedback only when a recipe actually completes. No completion sound for changing inputs, failed recipes, or blocked outputs.
- Make the effect audible to nearby players without playing it twice for the player interacting with the GUI.
- Add clear status messages such as **Missing ingredient**, **Output full**, and **Maximum infusions reached** instead of silently stopping.
- Add subtitles for new sounds and a visible completion flash for accessibility.
- Keep audio short and subtle when many machines operate nearby.
- Ensure all recipe and inventory operations remain authoritative on the server; clients should not duplicate outputs, sounds, or effects.

## 7. Configuration, guidebook, JEI, and compatibility

- Update the guidebook with Curios behavior, relic activation controls, enchantment descriptions, infusion effects, recipes, cooldowns, and stacking/compatibility rules.
- Add/update JEI integration for all new Transmutation Table and Celestial Infuser recipes, including the two independent outputs associated with each mapped source item.
- Keep tooltips consistent: effect, valid equipment/slot, activation mode, cooldown, infusion limit, and incompatibilities.
- Add server configuration for relic cooldowns, inventory versus equipped activation, duplicate-effect behavior, and optional Curios totem activation.
- Add a configuration or tag-based route to replace candidate source item IDs without changing the effect mapping code.
- Preserve existing worlds and player data. Existing items, enchantments, infusions, and recipes must remain valid unless a documented migration is unavoidable.
- Check dependency metadata and runtime checks so Curios remains a soft/optional dependency.

## 8. Suggested implementation phases

### Phase 1 — Audit and architecture

- Inspect the 0.0.2 item registry, recipes, enchantments, infusions, config, and version metadata.
- Finalize the source-item matrix above against actual registry IDs; every source item must retain both output mappings.
- Add shared data structures/recipe validation for the two effect pathways.
- Confirm Curios version/dependency metadata for Forge 1.20.1 and ensure startup works without it.

### Phase 2 — Machine reliability and feedback

- Implement completion sounds, particles, status messages, and accessible feedback.
- Test output-full and invalid-recipe cases to ensure they do not trigger completion feedback or consume inputs incorrectly.

### Phase 3 — Enchantments and infusions

- Implement the six enchantments and four infusions with explicit levels, equipment restrictions, caps, and conflict rules.
- Add both recipe paths for every source item in the mapping table.
- Add data/registry validation to prevent one-sided source-item mappings.

### Phase 4 — Relics and optional Curios

- Implement the six relics, shared activation keybind/selection, server-side cooldown logic, and Curios slots/tags.
- Verify inventory-only behavior when Curios is absent, and configured behavior when it is present.

### Phase 5 — Documentation, compatibility, and release

- Update guidebook, JEI, tooltips, config comments, and changelog.
- Test upgrades from 0.0.2 worlds and verify all registered IDs remain stable.
- Run dedicated-server and multiplayer tests before releasing 0.0.3.
- Update mod, changelog, and metadata version numbers consistently to **0.0.3**.

## 9. Acceptance tests

- [ ] RelicWeave starts and runs normally without Curios installed.
- [ ] With Curios installed, supported charms function from valid locations and do not produce duplicate effects.
- [ ] Every source item in the mapping table has both a Transmutation enchantment path and a Celestial Infuser infusion path; automated validation fails if either is missing.
- [ ] All six enchantments respect equipment types, levels, caps, cooldowns, and balance restrictions.
- [ ] All four infusions respect their armor-piece restrictions and the three-infusion limit.
- [ ] Repeated copies of an item or effect cannot bypass effect caps, duplicate prevention, or cooldowns.
- [ ] Moving, dropping, equipping, unequipping, dying, respawning, changing dimensions, or reconnecting cannot reset relic cooldowns or duplicate a temporary effect.
- [ ] Machine completion feedback plays once on success and never on failure or blocked output.
- [ ] Multiplayer clients cannot duplicate recipes, output items, sounds, particles, or effect activation.
- [ ] Existing 0.0.2 items, recipes, infusions, and player data survive an upgrade.
- [ ] Guidebook, JEI, tooltip, configuration, and recipe mappings agree with the implemented registry.
- [ ] Version metadata and release changelog consistently identify version 0.0.3.

## Out of scope for 0.0.3

Defer a new ore/material tier, bosses, dimensions, relic skill trees, and a large socketing system. The existing Celestial progression should be expanded and polished before adding another progression layer.
